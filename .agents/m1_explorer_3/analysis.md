# M1 Exploration Analysis: Legal Guardrails, Gemini TTS Voice Mappings & Unified Skill Registry Architecture

## Executive Summary
This analysis presents the architectural design for Requirement R1's **Legal & Identity Guardrails**, **Licensed Gemini TTS Voice Mappings**, **Unified Skill Registry** (`app/lib/skills/`), and **Database Compatibility** with `show_templates` and `scripts/seed-templates.ts`.

The system decouples comedic formats, rhetorical spines, and joke mechanics from living-person biometrics to guarantee compliance with Right of Publicity laws (Cal. Civ. Code § 3344, NY Civ. Rights Law § 50-51) and AI safety frameworks, while mapping each host persona to one of 7 officially licensed Google Gemini 3.1 Flash TTS prebuilt voices (`Charon`, `Orus`, `Puck`, `Fenrir`, `Aoede`, `Kore`, `Enceladus`).

## 1. Legal & Identity Guardrails Architecture

### 1.1 Legal Context & Risk Analysis
- **Right of Publicity & Biometric Cloning**: Exploiting a living celebrity's name, voice, or physical likeness without authorization creates legal exposure under state Right of Publicity statutes and pending federal digital replica legislation (e.g. NO FAKES Act).
- **Parody, Satire & First Amendment Protection**: Formats, rhetorical structures (e.g., 3-act escalation, rule-of-three, thesis-evidence-analogy, deadpan headline commentary), and comedic tropes are firmly protected under First Amendment jurisprudence (*Campbell v. Acuff-Rose Music*, *Hustler Magazine v. Falwell*).
- **Core Guardrail Principle**: *Prioritize genre craft, format structure, and rhetorical spines over proprietary living-person biometrics.*

### 1.2 The Guardrail Triple-Lock System
To ensure total compliance across all generation paths:

1. **Craft-First Persona Decoupling**:
   - Host definitions encode *stylistic craft vectors* (mean sentence length, profanity register, outrage/affability balance, lexical idiosyncrasies, rhetorical pacing) rather than biographical identity or biometric mimicry.
   - Persona prompts instruct the LLM: *"Adopt the rhetorical cadence, escalating analogical comparisons, and comedic timing of a British investigative satirist. Analyze public facts using satirical inquiry."*

2. **Strict Licensed Prebuilt TTS Voice Policy**:
   - Audio synthesis relies exclusively on Google Cloud's 7 licensed Gemini prebuilt voices.
   - No custom voice cloning, no voice actor scraping, and no acoustic deepfake models.

3. **Satirical Watermarking & Transparency**:
   - All generated shows, audio tracks, and transcripts are tagged with clear satirical parody disclaimers:
     `"Generated by Interdimensional Cable AI Comedy Orchestrator. Satirical parody created with licensed Google Cloud Gemini TTS."`

### 3.1 File Structure in `app/lib/skills/`

```

├── schemas.ts                   # Zod v4 validation schemas for all skill entities

├── db-adapter.ts                # Bidirectional converters between ShowSkill and DB ShowTemplate
├── index.ts                     # Central clean export barrel
```

### 3.2 Unified Registry Interface & API (`registry.ts`)
The `SkillRegistry` provides fast in-memory indexing and robust lookup strategies:

```typescript
export interface ISkillRegistry {
  // Direct lookups
  getSkillById(id: string): ShowSkill | undefined;
  getSkillByName(name: string): ShowSkill | undefined;
  getSkillsByArchetype(archetype: ShowArchetype): ShowSkill[];
  getAllSkills(): ShowSkill[];
  getDefaultSkill(archetype?: ShowArchetype): ShowSkill;

  // Smart resolution
  resolveSkillForShow(identifier: string): ShowSkill;

  // Dynamic registration & validation
  registerSkill(skill: ShowSkill): void;
  validateSkill(data: unknown): ShowSkill;
}
```

#### Smart Resolution Algorithm (`resolveSkillForShow`)
1. **Exact ID Match**: checks if `identifier` matches `skill.id` (e.g., `"investigative-desk"`).
2. **Slug Match**: checks if `identifier` matches `skill.slug`.
3. **Alias Match**: checks if `identifier` matches any string in `skill.aliases` (e.g. `"john-oliver"`, `"seth-meyers"`).
4. **Name Substring Match**: case-insensitive normalization matching `skill.name` (e.g., `"Last Week Tonight with John Oliver"`).
5. **Archetype Fallback**: if identifier matches an archetype (`"writers_room_desk"` or `"conversational_podcast"`), returns the archetype default.
6. **Global Fallback**: returns default desk show skill (`investigative-desk`).

## 4. Database Compatibility & Seeding Architecture

### 4.1 Compatibility with `db/schema.ts` (`showTemplates`)
The `showTemplates` table schema:
- `id`: `uuid` primary key
- `name`: `text` (e.g., "Last Week Tonight with John Oliver", "The Joe Rogan Experience")
- `showType`: `text` ("monologue" | "conversation")
- `referenceImageUrl`: `text` (e.g., "/templates/john-oliver.png")
- `hosts`: `jsonb` array of host objects
- `notes`: `text` format/craft summary
- `isDefault`: `boolean`

#### Zero-Migration Forward Compatibility
- PostgreSQL `jsonb` natively supports storing enriched host metadata (`{ name, role, ttsVoice, personality, personaCraft, position }`) without schema changes.
- The `db-adapter.ts` provides seamless hydration:
  - `skillToDbTemplate(skill: ShowSkill): NewShowTemplate`
  - `dbTemplateToSkill(template: ShowTemplate): ShowSkill` (reconstitutes missing rhetorical spines/voice vectors using the registry if a custom user template is passed).

### 4.2 Enhanced Seeding Script (`scripts/seed-templates.ts`)
Instead of maintaining disjoint hardcoded templates in `scripts/seed-templates.ts`, the seed script imports all registered default skills from `app/lib/skills/`:

```typescript
import { getAllSkillsAsDbTemplates } from "@/app/lib/skills/db-adapter";

async function seedTemplates() {
  const defaultTemplates = getAllSkillsAsDbTemplates();
  for (const template of defaultTemplates) {
    const existing = await db.query.showTemplates.findFirst({
      where: (t, { eq }) => eq(t.name, template.name),
    });

    if (existing) {
      await db.update(schema.showTemplates)
        .set(template)
        .where(eq(schema.showTemplates.id, existing.id));
      console.log(`  ✓ Updated "${template.name}"`);
    } else {
      await db.insert(schema.showTemplates).values(template);
      console.log(`  + Seeded "${template.name}"`);
    }
  }
}
```

This guarantees 100% synchronization between the in-memory skill definitions and the Postgres database catalog.
